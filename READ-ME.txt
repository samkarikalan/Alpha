Independent tournament matches — consolidated updated files

SCOPE
Tournament match handling only. Existing ordinary rounds continue through their existing session/round database path. Tournament may keep its setup locally or sync it separately. Scoreboard tournament discovery and scoring use tournament_live_matches; they do not read tournament snapshots or tournament court-session records.

SUPABASE STATUS: ALREADY APPLIED
Project SCSDB has the independent publication/password RPCs and direct-publication support. Public clients cannot call these functions or read private match passwords. Existing scores, approved results and snapshots were not edited or deleted. The SQL in deployment/ is included as reference; do not run it again on SCSDB.

STILL REQUIRED
1. Replace and deploy the existing scs-app Cloudflare Worker using deployment/SCS-Worker-independent-matches.js. Keep the existing secrets/bindings. Do not use an older Worker file from a previous ZIP.
2. Upload the JavaScript files at the ZIP root to the existing app root. Keep the source contract/instructions with the project. This consolidated update includes the previous lifecycle and Start Event changes.
3. Close/reopen or update Tournament and Scoreboard on all devices. Do not clear app/site data: it contains your local setup, saved scores and pending work.
4. Open Tournament and use Sync now, or assign a match. Previously saved assigned fixtures are recovered into the independent match queue. Once publication is confirmed, the assignment notice says Available in Scoreboard. Refresh Scoreboard on the same or another device.

Worker check: POST /tournament/live with {"action":"capabilities"} must return protocol:2, matchSync:true and directPublication:true. Until the new Worker is deployed, match publication/password jobs show an update-required error and remain saved.

WHAT CHANGED
- An assigned Group, Team or Knockout match is saved locally and published directly to the match table. It does not wait for the tournament or session snapshot to upload.
- Match publication/password/score/approval jobs have their own sync lane. A stalled old tournament backup cannot stop this lane. Each independent match failure remains visible and does not stop other match jobs.
- Court allocation in an open local tournament uses the local parent allocation. KO starts/assignments can use locally saved court sessions. Neither needs a server tournament record before publishing a match. Occupied physical courts are still protected atomically by the match table.
- Match passwords are private and tied to the match, with no tournament-record prerequisite. Existing password values for current match records were preserved when present.
- Scoreboard no longer downloads full tournament snapshots in its background club download, and tournament discovery/history submission has no snapshot fallback.
- Old tournament snapshot jobs on a Scoreboard device are retained rather than sent through the legacy tournament path. Saved tournament results can be resubmitted from device History through their match record.
- The sync panel separates match-delivery pending counts from tournament-backup pending counts. An old backup error may still show ! Sync; it does not mean an independently published match is missing from Scoreboard.
- Final scores need a server receipt before being called sent. Organizer approval remains a separate match action, and approved scores remain immutable to every scoring device.

ROUNDS ARE UNCHANGED
Ordinary rounds still load from sessions, start with their existing setup and write points/results back through their existing session/round handlers. They are not published as tournament matches. A real Scoreboard browser regression verified this path and verified that it did not issue tournament-table reads or match-table score/publication writes for the round.
